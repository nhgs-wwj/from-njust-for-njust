## 实验代码说明：

实验的完整工程在empty_proj文件夹中，基于keil开发，是完整的工程代码，应该已经包括大部分的实验任务的要求。目前代码中主要由两个按键控制4个模式，P1.4长按切换工作模式，模式0用于日常debug与测试等等，可用于各位自由编辑；模式1是LED模式，一般对应实验的第一个任务，其中，P1.1短按以切换颜色，P1.4短按以切换LED的闪烁频率；模式2是红外循迹模式；模式3是避障模式，P1.4短按切换避障方式，一个是利用红外测距避障，一个是利用车前的碰撞开关避障。

使用方法大致如上，其他的具体问题各位可以借助AI来了解本工程，这在当下是十分轻松的。接下来简单介绍下代码，如同我们日常开发的简单裸机程序，一般都需要底层初始化层，系统和底层各种外设等的初始化等，硬件驱动层，比如本工程中的hardware层，应用控制层，利用硬件层的接口在上层完成逻辑控制与算法等，本工程涉及较简单，main中即可实现，以及可能还需要的通用工具层等，比如这里的pid.c。实验中，想要实现一个模块化的，方便拓展的，多功能的，这里采用定时器中断实现循环扫描切换、任务调度与实现。各模块的设计与实现中基本都是留出驱动接口、共享变量等类似的设计理念的，一定程度上应该方便各位的参考与二次开发等。如果有些函数存在过度封装或者不知所云的情况，那大致是由于实验中间任务所需或者代码衔接人员配合有误导致，各位自行优化即可。

因为工程已经有一定时间了且我目前无法验证，所以如果使用中发现工程有一些有问题的地方，请告知，并欢迎提出你的修正或者优化方法。

## 可能的其他问题：

- 电机有编码器为何没有做闭环？我们尝试发现即便是正常的电机力矩都小的可怜，带载情况更是惨不忍睹，所以我不认为做了闭环就能在速度响应等方面有优势。
- 硬件问题：小车使用年头过于长了，可以说所有外设和模块都没问题的小车少之又少，所以大家最好提前测试小车各个模块的好坏，学会利用调试找问题。
- 实验给的教程和一些例程记得似乎是基于CCS开发的，大家当然也可以尝试，听说照着例程改一改，也还是可以正常的完成任务的，另外在当今AI的加持下，一定更是不在话下了。
- 由于当时分工的任务我并不负责报告的撰写，所以报告的绝大部分工作都来自于我的队友，所以报告就不开源在我这里了。
